## Что поменять в коде

1. **Ниша «бьюти»** — вместо `commonRules` + `nichePrompt` отдавать `01-core.md`. Остальные ниши пока на старом промпте.
2. **Режим записи** — выбирать один блок: есть YCLIENTS/DIKIDI → В; иначе есть `bookingLink` → Б; иначе → А. Старое сообщение №5 со ссылкой убрать.
3. **Метки в ответе модели** — вырезать перед отправкой клиенту:
   - `[[NOTIFY_OWNER: …]]` → уведомление администратору (ТГ / МАКС / сайт). Бот продолжает отвечать.
   - `[[BOOKING_REQUEST: …]]` → уведомление «новая заявка на запись» с полями. Бот продолжает отвечать.
   - `[[HANDOFF]]`, `[[NO_REPLY]]` — как сейчас.
4. **Метрика «звал администратора»** — считать только `NOTIFY_OWNER` с причинами вне жалоб, опозданий и отмен. `BOOKING_REQUEST` — это заявка, её считать в конверсию, а не в вызовы администратора.
5. **Имя профиля** — передавать `displayName` из канала в блок «Что известно про клиента».
6. **Настройки владельца по темам** — хранить по ключам Т1–Т16 + «Прочее»; собирать блок «НАСТРОЙКИ САЛОНА» по шаблону. Свободный текст — разбирать при сохранении (`04-owner-text-parser.md`).
7. **Оси стиля из кабинета** — превращать в тексты тем по таблице в `03-salon-settings.md`. Дефолт эмодзи сменился: раньше «одно на всю переписку», теперь «в каждом втором-третьем сообщении» — `rare` остаётся как явная настройка владельца.
8. **Тексты «в базе ничего не нашлось»** и **ритм вопросов** — заменить на новые из `03-salon-settings.md`.
9. **Блок часов работы** («сервис откроется в …») — убрать, его заменяет Т16.

## Что исправлено по сравнению с версией 1

| Было | Стало |
|---|---|
| Семь мест объявляли себя «главнее всего» | Один порядок приоритетов в начале |
| Персона «поверх всего» одним текстом | Темы Т1–Т16: заполненная тема заменяет только своё правило |
| Запрет «уточню», но тексты для пустой базы велели «скажи, что уточнишь» | Одна формула: «передаю администратору» + метка, слово «уточню» убрано отовсюду |
| Без системы записи — запрет называть время и одновременно «закрой двумя слотами» | Три режима записи, в каждом своё честное поведение |
| Цены складывать запрещено, время — обязательно, «ориентир» — разрешено | Складывать можно, итог — ориентировочный, вилка остаётся вилкой |
| «Дорого»: два разных правила, одно обещало стойкость | Одно правило, стойкость не обещаем |
| Вопрос в конце: три разные команды | Вопрос — только если без него не сделать шаг; ритм вопросов согласован |
| 2 слота в одном месте, 3 в другом | 2 варианта |
| «Старая запись снята» без доступа к записи | Перенос/отмена — через инструменты или через администратора |
| «Спасибо, посмотрю» на ссылку | Ссылку не видим — просим описать; фото — видим и описываем |
| «Живой менеджер» | ИИ-администратор Стэлакс, честно на прямой вопрос — по умолчанию; владелец может задать иное |
| Хвосты от продажи программ (CRM, тарифы, пробный период) | Убраны |
| «Администратор, она свяжется», «женские» эмодзи | Нейтрально; о себе — без рода |
| Эмодзи без правил о тоне | Добрые и спокойные, одно на переписку по умолчанию; чаще — настройкой владельца |
| Жалобы — общая фраза | Не решаем и не обсуждаем закон, передаём владельцу со сводкой |

| Вопросы для выбора услуги — одна строка | Короткий список по пяти направлениям |
| Блок записи на английском | На русском |
